# 校园集市舆情分析项目

面向校园管理人员的安全舆情监测、风险研判与报告平台。系统从校园集市帖子中识别安全相关内容，完成情绪、地点、问题、诉求、风险评分和事件聚合，并通过 Vue 管理端展示。

## 当前数据

- 主数据文件：`posts(2).json`
- 有效帖子：9,753 条
- 时间范围：2026-05-26 至 2026-07-15
- `posts(2).json` 已包含原 `posts.json` 的 907 条帖子，不应将两个文件直接相加。
- 后端启动时按帖子 ID 自动增量同步，不会重复导入已有数据。

## 启动方式

后端要求 Java 17 及 Maven：

```powershell
cd backend
mvn spring-boot:run
```

前端要求 Node.js：

```powershell
cd frontend
npm install
npm run dev
```

默认地址：前端由 Vite 输出，后端 API 为 `http://localhost:8080/api`。

## 分析规则 2.0

核心安全类别保持不变：诈骗与财产安全、消防与用电安全、治安与人身安全、校园交通安全、宿舍设施问题、食堂与餐饮问题、突发事件。

规则 2.0 的主要变化：

- 使用带权短语和上下文组合，不再用“买、卖、出、钱”等单字判断诈骗；
- 普通二手商品描述会被排除，只有明确的被骗、诈骗、收钱不发货等证据才进入安全分类；
- 排除考试“爆炸”、实习“跑路”、“救命”等常见网络隐喻；
- 每条安全分类附带置信度、细分话题和分析版本；
- 风险同时考虑事件严重性、证据置信度、情绪、紧迫性、浏览量和互动量；
- 事件按“安全类别 + 细分话题 + 自然周”聚合，ID 稳定，避免把数十天内不相关的帖子合并。

规则分析只用于辅助筛查，高风险内容仍应由管理人员人工复核。

## 数据与分析接口

- `POST /api/data/import`：按 ID 增量导入 JSON 数组；
- `GET /api/data/stats`：数据量、分类、情绪、风险和分析质量；
- `POST /api/data/reanalyze`：按当前规则重新分析；
- `GET /api/settings`：读取数据库中持久化的风险阈值、分类和自定义关键词；
- `PUT /api/settings`：保存设置并自动重新分析全部帖子；
- `GET /api/analysis/extensions/task2`：查询任务二扩展状态；
- `POST /api/analysis/extensions/task2/run`：任务二统一执行入口。

## 任务二扩展

任务二标准尚未提供，当前实现只固定调用和数据契约，不猜测评分规则，也不会影响核心分析结果。

## 自定义分类

在“系统设置 → 安全议题分类”中新增分类时，需要同时填写至少一个不少于 2 个字符的识别关键词。保存后系统会：

1. 将分类、关键词和风险阈值持久化到 H2 数据库；
2. 自动按新规则重新分析帖子和事件；
3. 将新分类同步到舆情监测和事件管理的筛选项；
4. 在刷新页面或重启后端后继续保留设置。

内置七类使用高精度组合规则；删除内置分类会停用该类识别，自定义分类则按配置的多字关键词识别。

收到标准后实现 `AnalysisTaskExtension` 即可复用数据库中的标准化帖子字段。请求体约定可包含：

```json
{
  "standard": {
    "version": "标准版本",
    "dimensions": [],
    "rules": {},
    "thresholds": {}
  }
}
```
