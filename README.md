# 校园安全舆情平台

面向校园管理人员的安全舆情监测、人工研判、事件处置和报告平台。前端采用 Vue 3，后端采用 Spring Boot；默认使用本地 H2 数据库，可选接入兼容 OpenAI `/chat/completions` 协议的智能模型。

同步结果为：安全相关 194 条、疑似但无法确定 34 条、非安全内容 7562 条；五份文件共包含 7335 条评论。帖子与评论全部导入，评论通过帖子 ID 关联并以去标识化方式展示。

最终分类标准来自《分类.docx》，共 18 类：个人安全、意外伤害、消防与电气安全、建筑与设施安全、食品与公共卫生、交通安全、网络与数据安全、财产安全、心理危机、实验室安全、公共秩序与活动安全、环境安全、自然灾害、政治与国家安全、仇恨与身份歧视、校园谣言与声誉风险、其他校园安全、疑似主题无法确定。

外部分类型号默认开启。此模式下“刷新事件聚合”不会覆盖五份 JSON 的最终分类，也不会清空人工复核和既有事件处置状态。

## 主要功能

- 舆情总览：安全帖子、风险等级、趋势、热点事件和处置进度。
- 舆情监测：按关键词、分类、情绪、来源、复核状态和排序方式筛选全部 7790 条帖子。
- 帖子详情：查看原帖、去标识化评论、分类依据、评论摘要，以及英文分类代码后的中文翻译。
- 人工复核：确认、修正、标记无关或撤销复核，操作人由登录会话确定。
- 事件管理：聚合安全相关帖子，记录状态、风险、负责人、截止时间和处置备注。
- 报告中心：查看日报、周报和事件报告，并在浏览器端导出 PDF。
- 数据管理：数据质量检查、增量导入、事件聚合刷新、权限信息和操作审计。
- 智能助手：无 API 时使用本地结构化数据回答；配置 API 后调用指定模型。
- 实时分类工作流：接入任务二末代三阶段逻辑，依次执行主帖/评论初筛、18 类完整分析和低中高风险评估；支持小批量试运行与正式写回。

## 环境要求

- Java 17 或更高版本
- Maven 3.9 或更高版本
- Node.js 20 或更高版本
- npm

## 首次启动

### 1. 启动后端（不接外部模型）

在项目根目录打开 PowerShell：

```powershell
cd backend
$securePassword = Read-Host "请输入管理员密码" -AsSecureString
$env:YUQING_AUTH_PASSWORD = [System.Net.NetworkCredential]::new("", $securePassword).Password
mvn spring-boot:run
```

管理员昵称默认为“管理员”。密码至少 8 位，切勿把真实密码写入 `application.yml` 或提交到版本库。后端地址为 `http://127.0.0.1:8080`。

### 2. 启动前端

另开一个 PowerShell 窗口：

```powershell
cd frontend
npm install
npm run dev
```

浏览器访问 `http://127.0.0.1:5173`。

### 3. 启动后端并接入智能模型

先停止 8080 端口上的旧后端，然后在 `backend` 目录执行：

```powershell
.\start-with-ai.ps1 -Model "qwen3.5-plus"
```

脚本会隐藏输入 API Key 和管理员密码。默认中转地址为 `https://vip.dmxapi.com/v1`；也可指定其他兼容地址：

```powershell
.\start-with-ai.ps1 -BaseUrl "https://你的地址/v1" -Model "你的模型ID"
```

也可以只在当前终端设置环境变量：

```powershell
$secureKey = Read-Host "请输入 API Key" -AsSecureString
$env:YUQING_AI_API_KEY = [System.Net.NetworkCredential]::new("", $secureKey).Password
$env:YUQING_AI_BASE_URL = "https://vip.dmxapi.com/v1"
$env:YUQING_AI_MODEL = "qwen3.5-plus"
```

Key 只保存在当前终端进程环境中，关闭终端后失效。

任务二实时分类默认复用上述模型配置。也可使用 `YUQING_TASK2_API_KEY`、`YUQING_TASK2_BASE_URL`、`YUQING_TASK2_MODEL` 单独配置。为避免历史数据导入时意外产生模型费用，自动实时分类默认关闭；服务器需要对新导入帖子自动分类时设置 `YUQING_TASK2_AUTO_CLASSIFY_IMPORTS=true`，单批最多 20 条。管理员也可在“数据管理—实时分类工作流”中先试运行前 5 条，再正式写回。

## 使用流程

1. 登录后先在“舆情总览”确认数据量和风险概况。
2. 进入“舆情监测”，筛选安全相关、疑似主题或待复核内容。
3. 打开帖子详情，结合主帖、评论摘要和分类依据完成人工复核。
4. 对需处置内容进入“事件管理”，填写负责人、截止时间和处置备注。
5. 在“报告中心”查看或导出阶段性报告。
6. 在“数据管理”检查数据质量、审计记录和事件聚合状态。

## 数据维护

- 五份最终分类 JSON 是当前权威数据源，后端每次启动会按帖子 ID 和评论 ID 同步。
- 已存在的人工复核字段不会被启动同步覆盖；既有事件处置状态也会保留。
- 增量导入单次最多 20000 条，空数组会被拒绝。
- 外部分类模式下，设置保存和评论导入只会刷新事件聚合，不重新生成最终分类。
- “清空所有数据”不可恢复，操作前应先停止后端并备份 `backend/data` 目录。

## 安全配置

- 登录会话默认有效 24 小时；连续错误登录会触发限流。
- 修改后的密码采用 PBKDF2-HMAC-SHA256 加盐存储，并兼容旧密码记录迁移。
- 跨域请求默认仅允许 `127.0.0.1:5173` 和 `localhost:5173`。部署到服务器时设置 `YUQING_CORS_ALLOWED_ORIGINS`，多个地址用逗号分隔。
- H2 控制台默认关闭；如无排障需要，不要设置 `YUQING_H2_CONSOLE=true`。
- API Key、密码和令牌不得写入源码、截图、报告或审计备注。

## 常见问题

- **页面提示网络连接失败**：检查 8080 后端和 5173 前端是否都已启动。
- **首次登录失败**：确认启动后端前已设置 `YUQING_AUTH_PASSWORD`；若曾在个人中心修改密码，应使用数据库中的新密码。
- **助手显示本地模式**：说明没有配置有效的 `YUQING_AI_API_KEY`，其他业务功能不受影响。
- **端口被占用**：先停止占用相应端口的旧进程，再启动新版本。
- **数据时间提示滞后**：这是数据文件本身的最新发布时间提示，不表示同步失败；以数据管理页的帖子、评论总数和关联率为准。
